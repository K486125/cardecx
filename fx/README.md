# fx — 카드 시전 연출 모음

카드를 쓸 때 터지는 연출을 한 파일에 하나씩 모아 둔 폴더입니다.
**연출 하나 = SVG 파일 하나**이고, 움직임(애니메이션)까지 그 파일 안에 들어 있습니다.

| 파일 | 카드 | 길이 | 피해 시점 |
|---|---|---|---|
| `sword.svg` | 목검 (wooden_sword) | 0.7초 | 0.3초 (베기 마무리) |
| `dualsword.svg` | 듀얼 검 (dual_sword) | 1.4초 | 0.5초 / 0.8초 / 1.1초 |
| `blossom.svg` | 벚꽃 (cherry_blossom) | 1.8초 | 0초 (회복은 바로 들어간다) |
| `forest.svg` | 숲의정령 (forest_spirit) | 5.4초 | 0초 (설치형 — 회복 5초 동안 남아 있다) |
| `whiteblossom.svg` | 흰꽃 (cherry_blossom_evo) | 5.4초 | 0초 (설치형 · 숲의정령과 같은 토템 형태) |
| `stone.svg` + `stone-impact.svg` + `stone-impact-ground.svg` | 돌 (rock) | 1.0~2.5초 + 0.85초 | 날아가는 시간이 끝나는 순간 (차징 단계마다 다름) |
| ↑ 같은 두 장 + `stone-dust.svg` | 바위 지옥 (rock_hell) | 2.0 / 2.5 / 3.0초 | 덩이마다 닰는 순간 + 돌가루 3회 |
| `windsmash.svg` | 바람 (wind) | 0.4초 | 0.2초 |
| `tornado.svg` | 토네이도 (tornado) | 2.8초 전진 + 0.6초 | 닿는 순간(2.8초) |

## 어떻게 쓰이나

1. `js/cards.js` — 카드에 `cast: '<이름>'`을 적습니다.
2. `js/board.js` — `CAST_STYLES`에 그 이름으로 한 줄 넣습니다.

```js
dualsword: {
  shape: 'lunge', band: 150, radius: 300,   // 사거리 표시 (CSS가 담당)
  hitMs: 500,                               // 피해가 들어가는 시점
  endMs: 1400,                              // 연출이 끝나 지워지는 시점
  fx: { file: 'fx/dualsword.svg', w: 1000, h: 420, hx: 700, hy: 210 }
}
```

`shape`은 사거리 표시를 고릅니다 — `'fan'`(부채꼴), `'lunge'`(일자 돌진),
`'circle'`(원형 범위, `radius`가 반지름),
`'throw'`(투첩 — 던지는 쪽에서 커서까지 포물선 + 착지 원. `radius`가 착지 원, `reach`가 최대 거리),
`'none'`(사거리 표시 없이 평소처럼 카드가 커서를 따라다닌다. 단일 회복 등).
사거리 표시는 CSS(`css/animations.css`)가, 연출은 이 폴더의 SVG가 담당합니다.

3. `playCastFx`가 그 SVG를 `<img class="cast-fx">`로 화면에 놓습니다.
   `<img>` 안의 SVG는 문서와 완전히 분리되므로, 파일 안의 `<style>`이 게임 CSS에 새지 않습니다.

## 새 연출을 만들 때 지켜야 할 것

- **기준점**: `hx`, `hy`가 그림 안에서 **타워 중심**이 되는 점입니다. 그 점이 타워 위에 놓입니다.
  왼쪽에서 날아드는 연출이라면 그만큼 왼쪽에 여백을 두고 `hx`를 오른쪽에 잡으세요.
- **크기 단위**: `w`, `h`는 스테이지 px입니다. `viewBox`와 같은 값으로 두면 1:1로 그려집니다.
- **시간**: 피해는 JS 타이머(`hitMs`)가 넣습니다. SVG 안의 애니메이션 시각을 바꾸면 `hitMs`도 같이 맞춰야
  칼이 닿는 순간과 피해가 어긋나지 않습니다. `endMs`는 연출 전체 길이보다 짧으면 안 됩니다.
- **transform 기준점**: SVG 안에서 CSS `transform`을 쓸 때는 `transform-box: view-box`를 켜고
  `transform-origin`을 viewBox 좌표로 적습니다 (예: `transform-origin: 700px 210px`).
- **회전으로 베기**: 원이 커지는 연출은 충격파처럼 보입니다. 크기는 거의 그대로 두고 회전·이동으로 베세요.
- 연출은 상대 화면·관전자 화면에서도 그대로 재생되므로(`writeCastFx`), 이 파일만 바꾸면 양쪽 모두 바뀝니다.
- `js/board.js`가 시작할 때 모든 fx 파일을 미리 받아 둡니다. 파일을 추가하면 자동으로 포함됩니다.
- **만들어 내는 파일**: `forest.svg`와 `whiteblossom.svg`는 풀·꽃잎이 많아 `*.gen.py`가 만들어 냅니다.
  그 파일들은 손으로 고치지 말고 스크립트를 고친 뒤 `python fx/forest.gen.py`처럼 다시 만드세요.
  (`.gen.py`는 배포본 dist/에 넣지 않습니다.)
- **이모지 주의**: `<img>` 안의 SVG에서도 이모지는 뜨지만, 💮처럼 글자가 들어 있는 이모지가 있습니다.
  흰꽃의 가운데 꽃은 이모지 대신 꽃잎으로 직접 그렸습니다.
- **설치형(shape: 'circle')**: 타워에 붙지 않고 **클릭한 자리 그대로** 놓입니다.
  그 원 안에 들어온 타워만 효과를 받으므로(board.js `_castTowersInCircle`),
  반지름은 타워 간격에 맞춰야 합니다. 스테이지 좌표로 **이웃 타워까지 212, 반대쪽 끝까지 372**이므로
  반지름 270이면 "가운데에 놓으면 3개, 위/아래에 놓으면 2개"가 됩니다.
  그림의 반지름(250)은 사거리(270)보다 조금 작게 두어 표시와 연출이 어긋나 보이지 않게 합니다.
  설치 자리는 시전자의 킹 타워 기준 좌표(fxDX·fxDY)로 상대에게 전달됩니다 — database.rules.json에 두 필드가 있습니다.

## 연출이 SVG 두 장인 경우 (투척)

`stone`처럼 **길이가 매번 달라지는** 연출은 SVG 한 장에 담을 수 없습니다.
돌은 꾹 눌러 차징한 만큼 1.0초에서 2.5초까지 느리게 날아가는데, `<img>` 안의 SVG는
바깥에서 재생 시간을 바꿀 수 없기 때문입니다. 그래서 이렇게 나눴습니다.

| 조각 | 무엇 | 길이 |
|---|---|---|
| `stone.svg` (`fx`) | 날아가는 돌 자체. 회전은 **무한 반복**이라 어떤 비행 시간에도 맞는다 | 무한 |
| `stone-impact.svg` (`impact`) | 착지해서 깨지는 순간 — 서 있는 부분 (섬광 · 빛줄기 · 파편), `#fx-layer` | 0.85초 고정 |
| `stone-impact-ground.svg` (`impactGround`) | 같은 순간의 바닥 부분 (눌린 자국 · 먼지 고리 · 균열 · 충격 고리), `#cast-ground` 안에 눕는다. 충격 고리 끝(반지름 180)이 `radius`와 같아지도록 줄여 놓는다 | 0.85초 고정 |
| 궤적 | board.js `_playThrowFx()`가 Web Animations API로 그린다 (포물선 + 그림자) | 차징에 따라 |

포물선은 **가로(등속)와 세로(올라갈 때 감속 / 떨어질 때 가속)를 다른 요소에 나눠** 줍니다.
한 요소에 둘 다 주면 `transform`이 서로를 덮어써서 직선으로 날아갑니다.

차징 표는 `CAST_STYLES.stone.charge`에 있습니다 — 20%마다 한 단계로
피해 `[20, 24, 27, 31, 35, 40]`, 비행 `[1.0, 1.4, 1.7, 2.0, 2.2, 2.5]`초.
**세게 던질수록 아프지만 느립니다.**

차징 단계는 연출 id에 붙여 상대에게 보냅니다(`stone@3`). `instantHits.type`이 20자
제한이라 필드를 새로 만들지 않았습니다 — 덕분에 `database.rules.json`은 그대로입니다.

## 쌓는 순서에 주의

`stone-impact.svg`를 처음 만들었을 때 먼지를 맨 위에 올렸더니 균열도 섬광도 다 묻혀서
회색 얼룩처럼 보였습니다. 터지는 연출은 **먼지를 아래에, 균열·빛·파편을 위에** 놓아야 합니다.
먼지도 꽉 찬 원이 아니라 **가운데가 빈 고리**여야 폭발로 읽힙니다.

또 `viewBox` 밖으로 커지는 요소는 잘립니다. 필터 영역(`x`/`y`/`width`/`height`)을 아무리
넓혀도 캔버스가 자르므로, **가장 크게 퍼졌을 때의 크기가 `viewBox` 안에 들어와야** 합니다.

## 바위 지옥 — 한 장으로 세 번 들어가는 카드

`stonehell`(`shape: 'throw3'`)은 차징이 없고, 누르는 순간 세 덩이가 함께 떠나
상대 타워 셋에 **각각 다른 시각에** 떨어집니다. 표는 `CAST_STYLES.stonehell.shots`입니다.

| 줄 | 타워 | 도착 | 피해 | 돌가루 |
|---|---|---|---|---|
| 위 | `left` (2행) | 2.0초 | 30 | 5 × 3회, 0.6초 간격 |
| 중간 | `king` (4행) | 2.5초 | 40 | 6 × 3회, 0.5초 간격 |
| 아래 | `right` (6행) | 3.0초 | 50 | 7 × 3회, 0.4초 간격 |

멀리(오래) 날아갈수록 아프고, 돌가루도 더 아프고 더 빠르게 들어갑니다.

**카드 한 장이 여러 번 들어가는 방법**: `deck.js`가 `opts.shots`를 보면
에너지와 덱 칸을 **지금 한 번만** 기록하고(`applyCardUse(..., slotIndex, ...)`),
덩이별 피해는 각자의 도착 시각에 `slotIndex`를 `null`로 넘겨 **피해만** 넣습니다.
3초 뒤에 덱 칸을 다시 쓰면 그 사이에 들어온 새 카드를 지워 버리기 때문입니다.

## 착지 원

> 2026-09-29 갱신: 아래 '타워 한 칸' 규칙은 이제 `stonehell`에만 해당한다. `stone`은 '범위에 닿으면 맞는다'로 바뀐 뒤
> 50 → 150(3×3칸) → **100(2×2칸)** 이 됐고, 두 타워 사이에 떨어뜨리면 둘 다 맞을 수 있다.
> 깨짐 그림도 두 장으로 나눴다 — 예전 한 장은 세로를 0.62~0.66배로 손으로 눌러 '누운 척'을 했는데, 바닥판은 18도만
> 눕기 때문에 그 납작한 타원이 거의 둥근 조준 원과 따로 놀았다(그 위에 판정 크기의 금빛 고리까지 겹쳐 있었다).
> 지금은 바닥 부분이 진짜 바닥판 안에서 둥글게 퍼지고, 크기도 판정 원에 맞춰 줄어든다.

(예전 기록)

`stone`과 `stonehell`의 `radius`는 **50**(지름 100 = 타일 한 칸 = 타워 한 칸)입니다.
처음에 110으로 뒀더니 원이 옆 타워까지 닿아 보여서 여러 개를 맞히는 것처럼 오해를 샀습니다.
타워 간격이 224이므로 반지름은 112보다 확실히 작아야 합니다.

## 토네이도 — 타일에 설치해 전진하는 연출

`tornado`(`shape: 'tile'`)는 **내 진영 타일 한가운데**에 놓이고, 거기서 오른쪽으로 일자로
전진해 타워를 칩니다. 타워가 선 칸에는 놓을 수 없습니다(내 타워든 상대 타워든).

돌과 같은 이유로 SVG 안에 '전진'이 없습니다 — 놓은 칸에 따라 거리·속도·크기가 달라지므로
이동과 확대는 `_playTornadoFx()`가 Web Animations API로 그립니다. 파일은 **제자리에서 도는
소용돌이**만 그리고, 회전이 무한 반복이라 어떤 이동 시간에도 맞습니다.

멀리서 올수록 오래 감기므로 **더 크고 더 빠르고 더 아픕니다**. 도착까지 걸리는 시간은
어디서 놓든 2.8초로 같아서, 멀리서 온 토네이도가 그만큼 빨라 보입니다.

| 놓은 열 | 반지름 | 닿는 줄 | 옆 타워 피해 | 킹 피해 |
|---|---|---|---|---|
| 0 (제일 왼쪽) | 209 | 셋 | 60 | 55 |
| 1~4 | 187~121 | 둘 | 55~40 | 50~35 |
| 5~7 (강 쪽) | 99~55 | 하나 | 35~25 | 30~20 |

**몇 개를 맞히느냐는 따로 정해 두지 않습니다** — 다 자란 크기에 닿으면 하나든 둘이든 셋이든
전부 맞습니다. 타워 줄 간격이 200이므로 반지름 100이면 두 줄, 200이면 세 줄에 닿습니다.
세 줄을 다 맞히려면 맨 끝(0열)에서 **가운데 줄**에 정확히 놓아야 합니다.
피해는 **타워마다 자기까지의 타일 수**로 따로 정해지므로, 한 번에 맞아도 킹과 옆 타워의
피해가 다릅니다. 닿는 타워가 하나도 없는 줄에 놓으면 그냥 지나가고 아무 피해도 없습니다.

## 상대 화면 좌표는 '시전자와 시점이 같은가'로 뒤집는다

`fxDX`·`fxDY`는 시전자 화면에서 맞는 쪽 킹 타워로부터 잰 값입니다. 받는 쪽 화면이
시전자 화면의 좌우 거울이면 가로를 뒤집어야 같은 자리에 놓입니다(`game.js _castFxPoint`).
**맞는 쪽이 'my'냐 'enemy'냐로 따지면 틀립니다** — 상대 진영에 쓰는 카드(투척·토네이도)는
받는 쪽에서 owner가 'my'로 뒤집혀 들어오기 때문입니다. 관전자는 p1 시점으로 봅니다.

## 화살 · 사랑의 화살 · 지진 · 붕괴 (2026-09-29)

이 넷은 SVG 파일이 없습니다. 활·화살·반짝이는 `board.js`가 인라인 SVG와 CSS로 그리고(`_spawnBow`, `_arrowSvg`, `_shotVisual`),
지진·붕괴의 무너지는 칸은 진짜 타일을 베낀 조각(`_quakeGround`)이며, 사랑의 화살 하트와 무너지는 토템은 `towers3d.js`가 3D로 그립니다
(`towers3dLoveHeal` · `towers3dLoveBreak` · `towers3dCrumbleTotem`). 화살은 꽂히는 거리에 따라 시간이 달라져서 한 장짜리 SVG에 담을 수 없습니다.
